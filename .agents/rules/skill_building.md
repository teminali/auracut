# Continuous Platform Improvement During Skill Building

Whenever you are tasked with building a skill using the `skill-builder` or any other method, you must treat this as a real-world test of the platform and editor tools.

**Rule Requirements:**
1. **Monitor Performance:** Actively evaluate the performance, reliability, and UX of the tools (e.g. MCP servers, CLI, editor integrations) as you use them.
2. **Proactive Improvement:** If you identify any bugs, friction points, or areas where the tools fall short (e.g. missing capabilities, poor error handling, unoptimized workflows), you must pause to fix and improve the underlying platform tools before or alongside building the skill.
3. **Never Ignore Friction:** Do not simply work around platform issues. A core part of building a skill is ensuring the platform itself is robust enough to support it natively.
